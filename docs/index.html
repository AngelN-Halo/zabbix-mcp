MCP · MONITORING

Zabbix MCP

Scoped read-only health, problem, and event queries for Zabbix.

Group allowlist →Define approved groups outside public source control.Tool reference →Explore bounded summaries, problems and recent events.Deployment boundary →Keep loopback-bound listeners behind access controls.
At a glance
The service aggregates monitoring status for an illustrative group allowlist and exposes six MCP tools. It does not acknowledge events or alter monitoring configuration.

Request path: Authorized client → private gateway → MCP / optional MCPO bridge → Zabbix API

Quickstart

  1. Copy .env.example to ignored .env; create ignored .env.upstream with your approved ZABBIX_URL and ZABBIX_API_TOKEN.
  2. Adapt the illustrative group search terms in groups.py privately; never commit a host inventory.
  3. Set a strong MCPO_API_KEY if using the OpenAPI bridge; configure allowed hosts and an authorized gateway.
  4. Review docker compose config locally, build, and verify with synthetic monitoring data before production use.
cp .env.example .env
# Create ignored .env.upstream with ZABBIX_URL and ZABBIX_API_TOKEN
# Set the upstream URL and token privately
# Privately configure group allowlists and MCPO_API_KEY
docker compose config >/dev/null
docker compose build

Do not commit a real .env, private certificates, API keys or inventory.

Deployment

This repository is an example, not a production deployment recipe. Use private configuration, approved service accounts and an access-controlled network. Inspect the resolved Compose settings on the deployment host; they may contain secrets.

Do not publish the service listener directly. Build success alone does not verify backend connectivity, caller authorization or safe output. Start with approved synthetic data and a rollback plan.

Tools & integration

MCP tools: zabbix_connection_test, zabbix_get_system_summary, zabbix_list_service_groups, zabbix_get_group_health, zabbix_list_active_problems, and zabbix_get_recent_events. Problem and event counts are bounded; host details in group health are opt-in.

GET /health reports local service status; it is not proof the upstream Zabbix API is available. The optional MCPO container converts the Streamable HTTP MCP endpoint to OpenAPI behind its own key.

Security

Example listeners bind only to host loopback. This is not sufficient protection for a remote-facing reverse proxy. Add authentication, authorization, TLS, Host allowlists and network policy; review monitoring outputs and logs for sensitive infrastructure data.

Scope account privileges to the required reads and review returned data, error messages and logs before attaching AI clients.

Validation & troubleshooting

Run python -m pytest -q with development dependencies. Test group scoping, cache refreshes, bounded problems/events, failures, client authentication and denied requests using approved synthetic data.

If a tool fails, check private configuration, container health, TLS trust, upstream reachability, caller authorization and the relevant backend permissions before broadening access. Avoid pasting secret-bearing Compose output into issues.
